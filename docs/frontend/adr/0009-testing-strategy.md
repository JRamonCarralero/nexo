# ADR-0009: Testing strategy

**English** · [Español](0009-testing-strategy.es.md)

- **Status:** Accepted (partly implemented)
- **Date:** 2026-10-22

## Context

Tests must check behaviour the user sees, run fast in CI and not depend on a running backend.

## Decision

- **Vitest** + **Testing Library** (jsdom) for units and components, with `fetch` stubbed. *Implemented.*
- **MSW** with mocks generated by orval for richer component tests, and **Playwright** + **axe** for end-to-end flows and accessibility in CI once the first real flow exists (sign in + create a task). *Planned.*

## Consequences

**Positive**

- Fast feedback; tests written from the user's point of view.

**Negative / trade-offs**

- jsdom is not a real browser: some behaviour only shows in Playwright.

## Alternatives considered

- **Jest:** slower and needs extra setup with Vite.
- **Cypress:** good, but Playwright is faster and covers more browsers.
